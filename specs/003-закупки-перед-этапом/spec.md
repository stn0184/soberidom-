## Проблема

Человек приезжает на участок и обнаруживает, что нет перчаток, саморезов
или второго рулона мембраны — и едет в магазин пятый раз. Всё, что нужно
для этапа, в продукте уже есть: BOM по этапам (`bom_items.stage_id`),
инструменты с привязкой к этапам (`project_tools.stage_codes`), цены и
отметки «куплено» в живой смете. Но живёт это на отдельных экранах
`/estimate` и `/tools`, а в момент, когда человек открывает этап в
конструкторе, ему ничего не говорит «перед тем как начать — купи вот это».

Второе: цена показана только за единицу (`₽/шт`), а на лесной базе доску
продают за куб. Новичок не может сопоставить прайс базы с нашей сметой.

## Решение

**Экран начала этапа** в конструкторе `/my/[purchaseId]/build`. Сейчас
выбор этапа (сайдбар, карта этапов `?stage=`, переход «Готово, дальше»
через границу этапа) сразу открывает шаг. Станет: выбор этапа открывает
экран начала этапа, шаг — по кнопке «Начать этап →» (или клику по шагу,
если шаги этапа уже начаты — тогда экран не навязывается, но доступен
по заголовку этапа в сайдбаре).
[УТОЧНИТЬ: здесь «экран не навязывается, если шаги этапа уже начаты», а в
приёмке клик по этапу в сайдбаре ДОЛЖЕН всегда показывать экран этапа —
что верно и что считать «начатым» (есть хотя бы один done-шаг? заходили
ранее?)? от этого зависит поведение сайдбара и проверяемость первого
пункта приёмки. И отдельно: обычный вход на `/my/[id]/build` без `?stage`
(сейчас US-007 открывает первый незавершённый шаг) — шаг или экран этапа?]

Содержимое экрана сверху вниз:

1. Шапка: цветной маркер, «Этап N · display_name», `intro`, чип
   `≈ duration_days дн.` (как на карте этапов).
   [УТОЧНИТЬ: `GET /api/my/[purchaseId]/build` сейчас не отдаёт
   `duration_days` (в ответе id/number/code/displayName/color/intro/steps),
   и самого роута нет в блоке «Код». Откуда экран берёт длительность —
   добавляем поле в ответ `/build` (тогда правится и SPEC §3.8) или отдаём
   его в `/supplies`? без ответа пункт приёмки про шапку не выполним.]
2. **«Перед этапом купите»** — материалы этапа: таблица `Материал ·
   Кол-во · Ед. · Цена · Сумма · ☐ куплено`. Позиции — из
   `calcEstimateDetailed`, отфильтрованные по `stageCode` этапа. Для
   `category = lumber` с `volume_m3 > 0` под ценой за штуку второй строкой
   `≈ N ₽/м³` (`priceMinor / volume_m3`, округление до рубля)
   [УТОЧНИТЬ: округлять до рубля (кратно 100 минорных) или, как сказано в
   приёмке, «до целого» минорной единицы? и что лежит в `pricePerM3Minor` —
   минорные единицы или рубли? от этого зависит и число на экране, и тип в
   API]. Галочка
   «куплено» — тот же `POST /purchased`, что в смете: отметка глобальная
   по материалу, синхронна со сметой и фин-отчётом. Прогресс «куплено X
   из Y» над таблицей, `storage_tip` — иконкой с подсказкой, как в смете.
3. **«И это понадобится»** — инструменты, у которых `stage_codes`
   содержит `code` этапа: название, бейдж купить / арендовать / одолжить,
   ориентир цены, `alternative` строкой «можно обойтись: …». Ссылка «Все
   инструменты →» на `/tools`.
4. Кнопка `xl` «Начать этап →» — первый невыполненный шаг этапа.
   Ссылка «Смета целиком →» на `/estimate`.

**Данные** — новый роут `GET /api/my/[purchaseId]/supplies?stage=<uuid>`:
`{ data: { materials: EstimatePosition[], tools: Tool[], currency },
meta: { needRegion } }`. `EstimatePosition` получает поле
`pricePerM3Minor: number | null` (считается в `detailed.ts`; смета его
пока не показывает). `Tool` — форма ответа `/tools`. Гард
`requireOwnerPurchase`, ошибки — формат SPEC 3.0. Если у покупки нет
`region_id` — материалы отдаются без цен (`priceMinor = 0`,
`priceMissing`), `meta.needRegion = true`, экран показывает подсказку
«Укажите город в смете — появятся цены».
[УТОЧНИТЬ: `calcEstimateDetailed` без `regionId` не работает — валюта берётся
из страны региона, а без региона функция возвращает `null`. Откуда тогда
берутся позиции BOM (отдельная выборка `bom_items` + `appliesTo`?) и какая
валюта уходит в ответе (`purchase.currency`)? без этого ветка «нет региона»
нереализуема.]
[УТОЧНИТЬ: галочка «куплено» без региона — `POST /purchased` в этом случае
отвечает `VALIDATION_ERROR` (см. purchased/route.ts). Чекбокс прячем,
блокируем с подсказкой или даём нажать и показываем ошибку? от этого
зависит, упрётся ли человек в непонятный отказ.]

**Состояния экрана** (design.md §2): загрузка — Skeleton шапки и двух
блоков; пусто (ни BOM, ни инструментов у этапа) — блок 2 и 3 заменяются
одним текстом «Список закупок для этого этапа ещё не составлен — всё
нужное есть в общей смете» + кнопка «Начать этап» остаётся; ошибка —
Alert + «Повторить»; мало данных — одна позиция без прогресса-«1 из 1»
странностей; много — таблица со sticky-заголовком, без пагинации.

## Чего не делаем

- Не меняем живую смету `/estimate`: `₽/м³` там не показываем, вкладки
  не трогаем (владелец: «смета остаётся как есть»). Отдельная S-правка,
  если понадобится.
- Не вводим отметку «куплено для этапа»: материал куплен один раз на
  весь проект, как в смете и фин-отчёте. Одинаковый материал в двух
  этапах — одна галочка в обоих местах.
- Не меняем схему БД и не наполняем BOM/инструменты — контент идёт
  отдельно (бэклог «до первых продаж»). Экран обязан жить с пустыми и
  частично заполненными данными.
- Не блокируем шаги, пока не куплено: экран — подсказка, не турникет
  (ВИДЕНИЕ §2.2).
- Не показываем закупки на самом шаге: у шага уже есть блок «Возьмите».
- Не делаем «общую закупку перед стройкой» отдельным экраном: этап 0
  «Подготовка» и есть начало, его экран начала играет эту роль.

## Приёмка

- КОГДА покупатель открывает этап из сайдбара или с карты этапов
  (`?stage=`), конструктор ДОЛЖЕН показать экран начала этапа с
  заголовком, `intro` и длительностью, а не первый шаг.
- КОГДА покупатель нажимает «Начать этап →», конструктор ДОЛЖЕН открыть
  первый невыполненный шаг этого этапа (или первый шаг, если все
  выполнены).
- КОГДА покупатель нажимает «Готово, дальше →» на последнем шаге этапа,
  конструктор ДОЛЖЕН показать экран начала следующего этапа.
- КОГДА у этапа есть позиции BOM, экран ДОЛЖЕН перечислить их с
  количеством, единицей, ценой и суммой в валюте покупки, а над списком —
  «куплено X из Y».
- КОГДА позиция — пиломатериал с ненулевым объёмом единицы, под ценой за
  штуку ДОЛЖНА стоять цена за кубометр, равная цене за штуку, делённой
  на объём единицы, округлённой до целого.
- КОГДА покупатель ставит галочку «куплено» на экране этапа, та же позиция
  в `/estimate` ДОЛЖНА показаться купленной, а в `/finance` — появиться
  трата; снятие галочки удаляет трату.
- КОГДА у этапа есть инструменты с его кодом в `stage_codes`, экран
  ДОЛЖЕН показать их с рекомендацией купить/арендовать/одолжить и
  альтернативой, если она задана.
- КОГДА у этапа нет ни позиций BOM, ни инструментов, экран ДОЛЖЕН
  показать объяснение и ссылку на смету вместо пустых таблиц, а кнопка
  «Начать этап →» — остаться.
- КОГДА у покупки не задан регион, экран ДОЛЖЕН показать материалы без
  цен и подсказку указать город в смете, а не ошибку.
- КОГДА запрос supplies не удался, экран ДОЛЖЕН показать Alert с кнопкой
  «Повторить».
- КОГДА чужой пользователь запрашивает `/api/my/<чужой id>/supplies`,
  API ДОЛЖЕН ответить 404 в формате `{ error: { code, message } }`.
- Ни одной русской строки в JSX новых компонентов: все — из `ru.ts`.
